# photoMan

一個**本地優先**的修圖工具，讓不懂專業修圖軟體的人也能改圖：
用滑鼠圈出要改的地方，AI 只改那一塊，**本機負責合成**。

> **鐵律：圈選範圍以外，像素逐 bit 不變。**

## 為甚麼需要這個工具

用對話式 AI 改圖有兩個常見的痛點：

1. **很難仔細指定要修哪一部分。** 文字是低頻寬的空間描述語言——
   「把左邊那個人手上的膠袋拿走」，模型必須先猜「膠袋」指的是哪一團像素。
   空間問題要用**滑鼠**解決，不是用更長的提示詞。
2. **質素嚴重下降。** 4K 進去，出來往往是 1080。這是模型規格，不是 bug——
   這類模型的輸出解析度是固定的（約 100 萬像素），與輸入無關。
   4K 是 830 萬像素，塌到 100 萬等於損失 88%，**而且發生在修圖之前**。

## 做法

```
使用者圈選區域          ← 空間通道，不是文字
      ↓
本機在原解析度裁出該區域（含一圈校驗環作上下文）
      ↓
只送這一小塊給模型
      ↓
量度校驗環 → 偏離過大就拒絕這張結果
      ↓
色彩／顆粒對齊
      ↓
只貼回遮罩範圍內 —— 遮罩以外從未被寫入
```

**為甚麼這件事只能靠本地合成。** 模型廠商自己承認會漂移：
FLUX.1-Fill-dev 的官方模型卡寫明填充區以外有輕微色偏、填充區邊緣有線條；
diffusers 的維護者說明 inpaint 權重是**刻意**訓練成跨接縫融合的。
所以這條保證必須是合成器的架構性質，不是關於任何模型的聲明。

## 開發

```powershell
py -3.12 -m venv .venv          # 必須 py -3.12，PATH 上的 python 不是 3.12
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

.\.venv\Scripts\python.exe -m pytest -q
```

**所有指令一律用 `./.venv/Scripts/python.exe`**，或在專案內使用 `py -3.12`。

## 開發慣例

- 所有文件、註解、介面文字一律**書面語中文**，不使用廣東話口語。
  程式碼標識符與技術術語保持英文。
- **註解解釋「為甚麼」，不解釋「做什麼」。**
- `src/photoman/composite.py` 與 `mask.py` 的任何改動都必須有對應測試——
  那兩個檔案是本案的保證所在。
