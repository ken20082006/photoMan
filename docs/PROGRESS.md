## 4. 不可違背的設計約束

改動任何一項都會推翻整個架構。

### 鐵律：遮罩外逐 bit 不變

**這是本專案成立的唯一理由。** 它必須是 `composite.py` 的性質，
不是關於任何模型的聲明。

模型廠商自己承認會漂移——FLUX.1-Fill-dev 的官方模型卡寫明填充區以外
有輕微色偏；diffusers 的維護者說明 inpaint 權重是**刻意**訓練成
跨接縫融合的。詳見 `design.md` §5.6。

**任何改動 `composite.py` 或 `mask.py` 的提交都必須有對應測試。**

### 三個品質層的契約是相反的

| 層 | 契約 |
|---|---|
| 確定性調整 | 無損，原解析度進出 |
| 局部生成 | `M_blend` 羽化帶以外逐 bit 不變 |
| 全幅生成 | 無（沒有可保留的東西） |

### 使用者不會用專業修圖工具

選取必須是**點擊**，不是套索。不給專業術語。每次生成前要有前後對照。

### 不做批次

修圖逐張進行。所以**不需要**任務佇列、斷點續跑、隔夜模式。
反過來，**延遲非常關鍵**——非同步回報進度與可取消比吞吐量重要。

## 5. 最貴的幾課（不要重踩）

### 兩個遮罩，不是一個

柔軟度**不可以**交給模型。PELC（CVPR 2026）證明在潛空間用軟遮罩做
線性混合不等於像素空間混合——VAE 解碼器非線性且空間糾纏，
要還原真值編碼，一半以上的體素需要落在 `[0,1]` 之外的 α，
結果是**無效的潛向量**，造成接縫、光暈、以及遠離遮罩處的劣化。

→ 模型拿到二值遮罩；柔軟度全部在像素空間的合成 alpha。

### 主要失效模式是頻寬，不是接縫

縮小去送沒有害，**放大回來是有損的**，把有效頻率上限砍半。
用**縮小倍率**判斷：`≤1.5×` 沒問題；`~2×` 邊緣；`>2–3×` 明顯低頻；
`>4×` 一眼看出。**羽化救不了它。**

→ 對策是放大後補跑一次低強度 hires pass（`design.md` §5.3.2 第 7b 步）。

### 填內洞不是可選項

**SAM 產生的遮罩是有洞的、不連續的。** 不填的話，模型會在物件內部
看到「保留」的指令，結果是物件沒有被完全移除。

### 幾何是最後的輸出設定，不是圖層

裁剪、旋轉、拉直不佔圖層。→ **遮罩永遠存在原圖座標，不需要任何變換。**
這消除了整個「幾何變更令下游遮罩失效」的問題類別。

### 真實照片與設計假設的落差（2026-09-18 實測）

設計一直假設 4K（8.3 MP）。**實測最大的一張是 42.2 MP**，
float32 線性光是 **506 MB**。→ **已定案（`design.md` §6.1c）：
底圖存原檔的 uint8 位元組（127 MB），只在處理裁切區時才線性化。**

**這個決定有一個比省記憶體更重要的好處：** 遮罩外的保證由
「避免寫入」升級成**字面上的位元組複製**——那些像素根本沒有經過
任何浮點運算，所以不可能有往返誤差。已用那張 42 MP 的照片實測：
**遮罩外 42.1 MP 之中，被動過的位元組 0 個。**

**推論（會影響圖層的評估方式）：** 逐點運算（曝光、白平衡、曲線）
與裁切可交換，所以 N 個調整層可以**合成成單一函數**，
一次套用——**沒有中間量化損失**。這正是「累積質素下降」的主要來源，
在這裡被結構性地消除了。

另外兩項：**HEIC 必須支援**（iPhone 預設格式，Pillow 讀不到，
沒有 `pillow-heif` 的話使用者第一張照片就失敗）；
**ICC 不可以假設是 sRGB**（iPhone 是 Display P3，直接當 sRGB 用會偏色）。

### 保證鏈的關鍵：uint8 → 線性光 → uint8 必須精確

這個失敗是**靜默的**——若不精確，整張圖每個像素都差一兩級，
看起來「差不多」，而保證已經破了。已實測 256 個灰階值全中、
1474 萬像素的真實圖片最大差 0，並寫成正式測試。

### 模型廠商聲稱的「保留」不算證據

Bria GenFill 聲稱「遮罩外像素完全保留，逐像素完美」，
但**沒有說明任何機制，也找不到任何第三方做過像素比對測試**。

→ 凡是模型自己講的，都不算證據。要驗，不要信。

### 兩個授權陷阱，都是「同類最好但不能用」

**EdgeSAM**（CPU 最快的分割）與 **CodeFormer**（最好的人臉修復）
**兩者都是 NTU S-Lab 非商用授權**。很容易順手選到它們。

另注意 **SAM 2 是 Apache-2.0，但 SAM 3 不是**——不要假設同家族共用授權。

  不得使用廣東話口語（唔、嘅、係、咗、喺、嗰、啲、佢、咁、乜、睇、搵、

  「完全離線可用」這個前提。
- **測試**：`pytest`。改動 `composite.py` 或 `mask.py` **一定要**有對應測試。
